## Restart summary

Wharfie's golden path remains a normal TypeScript/Node CLI that becomes one
approachable portable executable, runs locally or remains resident as a
durable service, and coordinates work across trusted machines without
requiring Node, containers, Kubernetes, or a hosted orchestration service on
the target machines.

The product exists to carry useful software beyond the coding session that
created it. It should preserve executable behavior and legible durable truth
so a person or later coding session can follow, recover, and evolve that work.

The settled project boundaries remain:

- nodes are trusted;
- one authoritative coordinator is acceptable initially when its durable
  authority is fenced and recoverable after coordinator loss;
- V1 and backward compatibility are abandoned;
- Wharfie is not general cloud IaC;
- finite Wharfie abstractions may use normal operator credentials to create
  only the resources they require;
- TypeScript/Node is the public authoring path, while measured Node-API, WASM,
  or other native hot paths remain possible behind versioned boundaries;
- exactly-once claims are made only where durable evidence and the managed
  destination's atomic effect semantics support them; and
- one executable and a machine-readable CLI remain the primary operator
  surface; a web UI is optional and later.

The standing working mode is local repository and Git CLI work rather than
PR/issue churn. Breaking changes are acceptable. Focused commits and pushes
are authorized. Use exact Node 24.13.1. Jest validation must disable coverage
and cache, run in disposable temp roots, and remove generated bytes
immediately. Never run native LMDB, native SEA creation on this Mac, or
block-device tools locally. Docker, live AWS, disposable hosts/EBS,
formatting, and other external mutation require explicit approval.

V84 preserved the read-only admission observer for the separate bounded Docker
proof path. V85 returns to the local-first product surface: it makes retained
run history discoverable from both source and packaged applications and
hardens the portable vanilla store so malformed retained bytes cannot be

## What V85 closes

### Fail-closed portable snapshot loading

Commit `74d4e2fde517e8ffaea380670994d77ce7cf531c` makes an existing vanilla
control snapshot one explicit integrity boundary.

Both writable and read-only opens now reject:

- malformed JSON;
- a null, array, or primitive database root;
- a null, array, or primitive table map;
- a null, array, or primitive primary-key bucket; and
- a null, array, or primitive sort-key record.

They fail with the stable `VanillaDatabaseIntegrityError` and
`vanilla-database-integrity-error` code before returning a client. The exact
existing bytes remain unchanged, including in writable mode. Records remain
ordinary maps whose values can contain arbitrary valid nested JSON, including
objects, arrays, nulls, booleans, numbers, and strings.

This closes the prior failure mode in which malformed persisted JSON could be
treated as an empty writable database and later overwrite durable evidence.
It does not add repair authority or infer a valid state from corrupt bytes.

### Shared verified history surface

Commit `af2ea2b220f4246713715f35ac9a1198401cfa32` exposes the ledger's
existing verified run directory through:

```text
wharfie ops list [--dir <app-dir>] [--limit <1..100>] [--cursor <opaque>] [--json]
<app> wharfie list [--limit <1..100>] [--cursor <opaque>] [--json]
```

Source mode resolves the strict application manifest from `--dir` or the
current directory. Packaged mode resolves only the embedded application
identity and deliberately has no directory override.

The listing contract is:

- application-scoped across all revisions, so a replacement SEA can discover
  older runs for the same application;
- ordered newest-first by immutable creation position;
- limited to 50 rows by default and at most 100 rows;
- continued only through an opaque, bounded, scope-bound cursor;
- read-only against already-existing control state;
- an honest empty page when the read-only store does not exist, without
  creating a directory or snapshot; and
- all-or-nothing: malformed pagination or any invalid item fails before a
  partial page is emitted.

The adapter delegates directory integrity to the execution ledger rather than
duplicating that protocol. The ledger reads a consistent directory page and
rebuilds each referenced run before returning it. Missing boundaries,
cross-application rows, corrupt rows, or mismatches fail closed. The command
then projects only these explicit safe fields:

```text
runId
revisionId
kind
status
version
lastSequence
createdAt
updatedAt
```

It omits application payloads, effect arguments and outcomes, evidence,
ownership fences, adapter paths, and redundant per-item application identity.

JSON output has this fixed page envelope:

```json
{
  "schemaVersion": 1,
  "kind": "wharfie.execution-ledger.run-page",
  "authority": "none",
  "authoritative": false,
  "integrity": {
    "verified": true
  },
  "scope": {
    "appId": "<logical-app-id>"
  },
  "items": [],
  "nextCursor": null
}
```

`nextCursor` is either a bounded opaque string or `null`. Human output uses a
safe table and prints a copyable cursor only when another page exists.
Listing grants no scheduling, cancellation, recovery, reconciliation,
ownership, or mutation authority.

Review caught and closed two boundary errors before publication: packaged
identity was narrowed to application scope instead of leaking revision/runtime
scope into history selection, and malformed pagination was rejected before
output. The final adapter also avoids reimplementing ledger invariants and
keeps redaction explicit.

## Honest boundaries

V85 exposes verified discovery, not a general observability subsystem:

- run logs are not durably appended, acknowledged, or publicly readable;
- listing does not expose event payloads, evidence, effect inputs/outputs, or
  terminal output;
- a verified directory projection reports durable ledger truth, not whether a
  current process or remote machine is alive;
- application-wide discovery intentionally crosses revision boundaries, but
  every returned row still identifies its exact revision;
- opaque cursors are continuation tokens for this scope and ordering, not
  authority, leases, snapshots reusable forever, or run identities;
- a missing store is empty history, while a malformed existing store is an
  integrity error;
- the portable vanilla adapter is appropriate for local/testing paths and does
  not itself provide a multi-process production control store; and
- no coordinator recovery, trusted multi-node placement, hosted service,
  systemd residency, or cloud lifecycle is added here.

The historical stash remains unrelated and untouched.

After that, design durable log append and acknowledgement before adding a
reader. Logs should have explicit retention, ordering, redaction, crash
recovery, and disclosure semantics; a terminal-only reader over ephemeral
output would not carry a user's work beyond the original session.

admission scan and the V83 bounded proof are still useful evidence work, but
neither should be run automatically. The V83 proof can consume meaningful
Docker disk, network, and time. Live AWS/EBS and block-device work require
