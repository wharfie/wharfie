# Wharfie checkpoint — shared source/SEA ledger operator

- **Date:** 2026-07-17
- **Branch:** `agent/strict-manifest`
- **Parent checkpoint:** resource-injection retirement
  (`2026-07-17-resource-injection-retirement.md`)
- **Scope:** give source and packaged applications one honest exact-run
  inspection/recovery implementation without exposing scan-based history,

Read this after the [resource-injection retirement checkpoint](2026-07-17-resource-injection-retirement.md).
The project remains free to make breaking changes, Node-first with future
native/WASI seams, trusted-node only, and centered on turning an ordinary local
CLI into a portable executable and then a durable service.

## Result

The same core leaf-command factory now backs both operator surfaces:

- installed source CLI: `wharfie ops inspect|recover`; and
- packaged artifact: `<app> wharfie inspect|recover`.

`ops run` remains source-only because it loads and compiles author source. The
packaged operator bundle receives only exact-run inspection and recovery, not
the authoring/build graph. The existing direct packaged `manifest` and
`metadata` commands remain siblings under the reserved `wharfie` namespace.

No public history/list or cancellation command was added. The bounded V3 run
directory remains an internal verified locator until its public disclosure,
pagination, and work-bound contracts are explicit. The retired scan-like
`ops list` and semantically false `ops cancel` surfaces stay deleted.

## Packaged authority boundary

A packaged command resolves identity lazily from the validated embedded
application-revision/runtime pair. It never derives authority from the current
directory, a source manifest, manifest CLI overrides, environment identity, or
the requested run.

After rebuilding and verifying an exact ledger partition, the operator requires
the persisted `run.appId` to equal the artifact's embedded app ID before it
emits output or mutates state. A cross-app run ID therefore fails closed and
does not acquire ownership. Recovery repeats that app check inside the mutation
ownership fence before changing the ledger and again on verified readback.

Authority is app-scoped, not revision-scoped. A successor artifact may inspect
or conservatively recover an older run from the same app because recovery never
loads or executes app code: it only releases an unstarted claim or records a
started attempt as uncertain. The run's pinned revision remains unchanged, and
the packaged operator revision is recorded as the recovery event actor. Any
future retry, continue, or dispatch command must separately require the exact
pinned executable revision.

## Storage and ownership behavior

- Adapter, control path, table, payload path/store identity, and local session
  namespace are resolved once into an immutable command-local configuration.
  Read-only preflight and writable recovery cannot drift between ambient paths.
- Inspection opens an existing local store read-only. Missing LMDB volumes or
  tables and absent vanilla snapshots are treated as missing exact runs without
  creating durable state. A malformed vanilla snapshot is surfaced rather than
  silently replaced with an empty view.
- The read-only ledger receives a payload store whose publication method fails
  before filesystem I/O, and both vanilla and LMDB adapters reject writes in
  read-only mode.
- Recovery first performs the read-only existence/integrity/app-scope
  preflight, then reopens writable state, acquires the existing per-app local
  ownership fence, rebuilds/rechecks the exact run, applies the conservative
  recovery transition, and verifies its readback.
- A packaged recovery currently requires LMDB. Explicit vanilla or DynamoDB
  configuration is rejected before opening state because those adapters do not
  yet implement coordinator ownership. The source CLI retains its explicitly
  documented diagnostic/manual behavior for non-LMDB adapters.
- A live resident session blocks packaged recovery; read-only inspection still
  succeeds. After an abrupt resident-process loss, the existing local session
  protocol permits one new manual owner to recover and release the run before a
  successor resident generation starts.

## Stable disclosure boundary

Source and packaged `--json` output use the same schema-v1 redacted view. It
contains verified lifecycle identities/statuses and sanitized event history,
but not activity inputs, caller metadata, terminal results, evidence,
transcripts, payload references, or attempt fencing tokens. Human output is
also generated by the same core formatting code.

The source-only CLI store/view and singleton inspect/recover modules were
deleted. Fresh Commander leaf instances are created for each parent so the
source and packaged programs cannot accidentally reparent one shared command
object.

## Portable proof

Under the exact pinned Node `24.13.1` and npm `11.12.0`, the clean package
verifier built a 138,120,144-byte Darwin SEA, copied it to a clean directory,
removed Node from `PATH`, and proved all of the following:

1. normal source and packaged application argv/stdin/stdout/stderr/exit behavior
   and a real target-specific LMDB activity still match;
2. installed-source and relocated-SEA exact-run inspection emit the same parsed
   redacted JSON;
3. the SEA rejects missing runs without creating work, rejects another app's
   exact run without output or mutation, and has no `list` or `cancel` command;
4. read-only SEA inspection succeeds while the same app's resident service owns
   LMDB, while confirmed recovery refuses and leaves the claim unchanged;
5. after `SIGKILL`, the packaged command releases the unstarted claim to
   `RUNNABLE`/`ABANDONED` without dispatching code; and
6. a successor resident process claims a fresh generation and later records a
   graceful `STOPPED` state.

Focused shared-operator, source CLI, packaged dispatch, unified configuration,
LMDB/vanilla read-only, and documentation suites pass. `npm run lint`,
`npm run typecheck -- --pretty false`, `npm run verify:package`, and
`git diff --check` pass; the tarball verifier reports 109 shipped files.
