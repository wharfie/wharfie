## Restart summary

Wharfie's golden path remains a normal TypeScript/Node CLI that becomes one
portable executable, can run locally or remain resident as a durable service,
and can coordinate work across trusted machines without requiring Node,
containers, Kubernetes, or a hosted orchestration service on those target
machines.

The product exists to carry useful software beyond the coding session that
created it. It preserves executable behavior plus legible durable truth:
revisions, artifacts, runs, invocations, attempts, effects, deployment state,
node state, and operator decisions.

The settled project boundaries remain:

- nodes are trusted;
- one authoritative coordinator is acceptable initially when its durable
  authority is fenced and recoverable after coordinator loss;
- V1 and backward compatibility are abandoned;
- Wharfie is not general cloud IaC;
- finite Wharfie abstractions may use normal operator credentials to create
  only the resources they require;
- TypeScript/Node is the public authoring path, while Node-API/WASM or other
  measured native hot-path implementations remain possible behind versioned
  boundaries;
- exactly-once claims are made only where a managed destination atomically
  enforces the effect identity with the business mutation; and
- the web UI remains optional and later, while one approachable executable and
  machine-readable CLI are the primary operator surface.

The standing working mode remains local Git CLI work rather than PR/issue
churn. Breaking changes are acceptable. Focused commits and pushes are
authorized. Tests must use exact Node 24.13.1, disable Jest coverage/cache, use
disposable `/private/tmp` roots, and remove all generated bytes immediately.
Never run native LMDB or block-device tools on the Mac. Live AWS, formatting,
purge-intended resources, and similar external mutation still require explicit
approval.

V80 defined the fixed zero-argument host-preflight SEA delivery. V81 closed
exact-source capture, same-generation build evidence, artifact records, and
immutable publication. V82 recorded a one-off real Linux/x64 SEA
build/execution observation, but its ephemeral runner and `whlp1` receipt did
not bind the exact proof tooling or invocation.

V83 promotes that proof boundary into committed production-shaped tooling. It
does **not** claim that the committed tooling has itself completed a Docker
proof run.

## Strict `whlp2` receipt

The receipt is schema version 2 with content-ID prefix `whlp2`. Its maximum
canonical transport size is 256 KiB. Validation forces:

```json
{
  "authority": "none",
  "authoritative": false
}
```

The receipt separates:

- **runner claims:** exact source/tooling commit, exact Git-bundle transport,
  exported driver/verifier/protocol byte observations, immutable local image
  ID, immutable container ID, fresh invocation ID, requested platform,
  execution mode, resource limits, isolation requests, and evidence channel;
- **builder claims:** the complete transported SEA artifact record;
- **independent guest observations:** clean detached checkout, reproduced source
  archive, regenerated entry bundle, held final executable bytes, relocated
  executable bytes, exact bootstrap archive, runtime environment, four
  executions, and guest cleanup; and
- **host-observed cleanup:** exact invocation/container identity, container
  absence, private workspace removal, and unchanged selected image identity.

Every subject ID and source commit is cross-bound. Source checkout transport
digest/size must equal the runner's complete prerequisite-free exact-HEAD Git
bundle. Reproduced source and entry bytes must equal the artifact record.
Published and relocated final bytes must equal its artifact ID and size.
Container, invocation, image, and cleanup identities must agree everywhere.

The exact Node bootstrap is:

```text
file:
  node-v24.13.1-linux-x64.tar.gz
size:
  56,127,068 bytes
sha256/base64url:
  etKPsXKpqwWT-GwaOeXCaNDY_D1ssBZ_RVtWVaem4v0
```

Filename, exact size, and digest are required independently by the guest and
receipt validator. Driver, verifier, and protocol source observations are
limited to 2 MiB each.

The execution classification remains deliberately narrow:

```text
linux-sea-startup-relocation-redacted-failure-observed
```

All four executions must match the deterministic V82 observation: status 1,
empty stdout, and exactly:

```text
AWS retained-storage host preflight SEA delivery failed.
```

The fourth execution must also prove that the controlled inherited
`NODE_OPTIONS` preload did not run. This records safe embedded startup,
relocation, fixed redaction, and specific preload non-extension. It does not
turn the unsupported Debian result into a successful AL2023 proof.

## Host driver boundary

The driver accepts only:

```text
<exact sha256 image ID> <canonical absolute output root>
```

It requires a completely clean repository and proves that live
driver/verifier/protocol bytes equal exact committed HEAD before exporting
them. The source is transported as one bounded Git bundle whose header contains
one exact `HEAD` and zero prerequisites.

The driver has no image-pull, image-build, volume-management, or privileged
container capability. Its Docker invocation fixes:

```text
pull:
  never
platform:
  linux/amd64
root filesystem:
  read-only
capabilities:
  none
privilege escalation:
  disabled
pids:
  512
memory / swap:
  6 GiB / 6 GiB
cpus:
  4
work tmpfs:
  4 GiB
/tmp tmpfs:
  512 MiB
input:
  read-only bind
log driver:
  none
network:
  unrestricted bridge
wall clock:
  30 minutes
```

Ambient proxy and AWS credential variables are cleared, and EC2 metadata
access is disabled through the standard environment switch. The bridge network
is intentionally still network-capable because the guest must obtain exact
Node/npm dependencies.

Every subprocess runs in a detached POSIX process group. Timeout, output
overflow, and interruption force-kill that group, wait for close, and use a
second bounded reap failure rather than immediately abandoning the child.
`SIGINT` and `SIGTERM` abort the in-flight Docker command and enter the same
container/image/workspace cleanup path.

Docker writes an exact immutable container ID to a private cidfile. On failed
startup, the driver waits through a five-second/100-millisecond CID-or-name
quiescence window after the Docker client closes. It then removes only the
immutable container whose exact image/name/invocation labels match this run.
Name fallback never authorizes removing a foreign container. A running
same-name container discovered before startup is treated as concurrent and is
not disrupted; an exact stopped stale container may be removed by immutable
ID.

Receipt construction occurs only after container absence, unchanged image
identity, and private-workspace removal. Publication stages and fsyncs
`proof.json` plus `SHA256SUMS`, then renames the directory and fsyncs the output
root. If an interrupt arrives after the final pre-publication gate, the
committed publication path is still printed rather than reporting an
ambiguous pathless failure.

## Guest verifier boundary

The host invokes only the committed verifier:

```text
/usr/local/bin/node /wharfie-input/verifier.js \
  --bootstrap <commit> <invocation-id> \
  /wharfie-input/repo.bundle \
  /wharfie-work/invocation-<invocation-id>
```

The bootstrap stage exclusively creates the exact fresh work root, records a
random 128-bit ownership token plus the directory device/inode in a private
marker, downloads and verifies exact Node 24.13.1, installs exact npm 11.12.0
into the owned root, and re-execs the verifier through that exact Node binary.

The owned verification stage:

- validates every tracked checkout entry as regular Git mode `100644` or
  `100755`;
- disables system/global Git configuration, replacement objects, and optional
  locks;
- proves the clean detached exact commit before and after work;
- lstat/realpath-checks every directly imported checkout module as a real
  regular file under the checkout;
- requires Node to be absent from the recorded runtime `PATH`;
- runs the production package command;
- loads only the bounded artifact record and re-observes stable regular
  artifact/record files;
- reproduces the source archive and entry bundle from the clean checkout;
- removes the original artifact and sidecar before relocated execution;
- rejects a symlinked relocation parent, copies only to the exact owned
  destination, re-observes the copy, and rechecks containment before each
  execution;
- runs the exact original/relocated/extra-argument/inherited-`NODE_OPTIONS`
  matrix with bounded process groups and output; and
- returns a canonical one-line JSON guest draft only after identity-bound
  cleanup.

Cleanup revalidates the original device/inode and marker, atomically renames
that exact directory to a random sibling quarantine, verifies the moved inode,
recursively removes only the quarantine, and proves both names absent. It does
not recursively remove a path whose ownership was not established.

## Honest boundaries

V83 is committed proof tooling, not new live environment evidence:

- the committed driver has not been invoked against a Docker image, so no
  `whlp2` receipt exists yet;
- V82 remains the only real Linux/x64 SEA build/startup observation, and it is
  still non-authoritative `whlp1` historical evidence;
- no successful AL2023 host-preflight execution exists;
- no live AWS, IAM, EC2, SSM, EBS, attachment, device, filesystem, flush,
  detach/reattach, service-health, or clean-account evidence was collected;
- no executable/build/dependency bytes are committed or retained;
- the selected local Docker image must already exist and is content-identified
  but not signed or attested by Wharfie;
- the unrestricted bridge network can reach internet, local-network, and
  link-local endpoints; cleared environment credentials do not create a
  network sandbox;
- official archive digest, package-lock integrity, and registry metadata are
  relied upon; there is no signature/transparency-log verification;
- artifact, record, and proof receipts remain unsigned;
- driver/verifier/protocol byte observations are host-runner claims tied to
  exact clean HEAD, not independently authenticated guest attestations;
- runtime bundle, SEA blob, and pre-injection Node source remain honest-builder
  evidence; the verifier independently reproduces source/entry and rehashes
  the final artifact but does not extract every intermediate from the final
  executable;
- the fixed redacted Debian failure cannot independently distinguish argument
  rejection from unsupported-host or collector failure;
- content hashes expose alteration but authenticate neither the runner nor the
  environment;
- the five-second Docker quiescence window bounds, but cannot mathematically
  exclude, an arbitrarily delayed daemon-side create;
- a hard host/process kill can still leave a running container or hidden
  staging directory; startup refuses to disrupt an observed running
  same-name container;
- staged directory publication is fsynced and atomic for cooperative
  execution, but Node does not provide a no-replace directory rename here and
  the output-root parent is not fully synchronized as a transactional object;
- a deliberately re-sessioned child can escape the guest process group, though
  it cannot keep guest failure return open beyond the reap deadline and the
  outer container teardown remains the final containment boundary;
- this proof does not add systemd residency, reboot recovery, automatic
  retries, provider-backed coordinator replacement, trusted multi-node
  placement, or exactly-once destination semantics; and
- the historical stash remains unrelated and untouched.
